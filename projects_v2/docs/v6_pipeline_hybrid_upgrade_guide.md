# Tutti V6 파이프라인 하이브리드 고도화 및 학습 가이드

본 문서는 Qwen2.5-0.5B 기반 오케스트레이션 생성 시스템(Tutti V6)의 구조적 한계를 극복하고, 음악적 유연성과 박자 강건성을 확보하기 위해 적용된 아키텍처 개선 내역 및 후속 학습 지침을 종합한 기술 문서입니다.

---

## 1. 아키텍처 진단 및 개선 목표

기존 V6 파이프라인은 17개 관현악 악기 파트의 정밀한 배치를 유도하기 위해 **100% 오프라인 FIM(Fill-in-the-Middle)** 구조로 설계되었습니다. 그러나 이로 인해 두 가지 치명적인 병목이 발생했습니다.
1. **선율적 흐름(Sequential Flow) 학습 부재**: 항상 완벽한 미래의 반주 문맥(`<SUF>`)이 주어지다 보니, 선율을 스스로 이끌고 발전시키는 작곡적 주도성이 저하되고 반주에 수동적으로 끌려다니는 현상이 발생했습니다.
2. **변박(Time Signature Changes) 취약성**: 음표의 소속 마디를 단순 나눗셈으로 분할하여, 곡 중간에 4/4에서 3/4 등으로 박자표가 바뀌면 누적 틱 오차가 발생해 전체 마디 정렬이 붕괴되었습니다.

**👉 개선 목표**: 기존 아키텍처의 정밀한 타겟팅 제어 능력을 유지하면서, **순수 Left-to-Right 생성 능력을 복원하고 누적 틱 기반의 무결점 시간 매핑을 통합**합니다.

---

## 2. 전처리 스크립트 핵심 수정 내역 (`preprocess_lmd.py`)

### ① 누적 틱 기반 사전 마디 맵(Robust Time Mapping) 구축
음표 파싱 전에 곡의 전체 박자표 변화를 누적 계산하여 각 마디의 정확한 시작 틱과 박자 수를 사전 배열(`bar_ticks`, `bar_bpb`)로 캐싱합니다.
* **효과**: 이분 탐색(`bisect`)을 통해 각 음표가 속한 마디 인덱스와 상대 시간 오프셋(`TIME=`)을 1틱의 오차도 없이 완벽하게 정렬하므로 변박이 빈번한 교향곡/클래식 곡에 극도로 강건해집니다.

### ② 하이브리드 청크 통합 (Causal + FIM)
기존 `build_fim_chunk` 외에 순수 악보 생성용 **`build_causal_chunk`**를 병합했습니다.
* **생성 전략**: 곡마다 16마디 간격으로 슬라이딩하며 타겟 악기 제약이 없는(`target_program: -1`) 순수 음악 전개 샘플을 추출하여 최종 `.jsonl`에 함께 직렬화합니다.
* **효과**: AI가 지정된 파트를 채우는 세션 연주자 역할과, 독창적인 멜로디 라인을 스스로 이끌어가는 메인 작곡가 역할을 동시에 훈련하게 됩니다.

## 3. 80,000 스텝 체크포인트 이어서 학습 (Resume Training)

데이터셋 구성 방식이 크게 고도화되었으나, **기존 8만 스텝까지 학습된 가중치를 버릴 필요가 전혀 없으며 적극적인 전이 학습(Transfer Learning)을 권장**합니다.

### 🟢 안전한 전이 학습이 보장되는 이유
1. **사전 규격의 완전한 일치**: 하이브리드 데이터셋 역시 `vocab_v6`의 645개짜리 고정 사전을 100% 공유하므로 입출력 임베딩 충돌이 발생하지 않습니다.
2. **사전 지식의 극대화**: 8만 스텝 동안 모델은 이미 17개 관현악 악기의 기본 음역대와 화성학적 어울림, 5토큰 문법을 완벽히 체득했습니다.
3. **도메인 적응 가속**: 탄탄한 기초 위에 질 좋은 선율적 흐름 데이터가 주입되므로, 처음부터 학습하는 것보다 훨씬 적은 스텝(예: 1~2만 스텝 추가)으로 최고 성능에 도달합니다.

### ⚙️ 학습 실행 명령어 가이드
체크포인트 디렉토리(`CKPT_DIR`)에 기존 가중치 폴더(`checkpoint-80000` 등)가 존재하면 `train.py`가 자동으로 이를 인식하여 최적화 상태를 이어나갑니다.

```bash
# 1. 수정된 하이브리드 전처리 가동
python3 preprocess_lmd.py

# 2. 직렬화 (jsonl을 train.bin / val.bin으로 변환)
python3 jsol_to_memmap.py

# 3. 분산 학습 가동 (3 GPU 예시)
CUDA_VISIBLE_DEVICES=1,2,3 torchrun --nproc_per_node=3 train.py
```
> **주의점**: 이어서 학습할 때 기존 학습률(`1e-4`) 또는 부드러운 스케줄러를 유지하여 기존 화성 지식이 급격히 파괴되지 않도록 유도하십시오.

## 4. 추론 파이프라인 정합성 요약 (`inference_v6_fixed.py`)

최신 추론 코드는 고도화된 학습 파이프라인과 **완벽한 문맥적 정합성**을 이룹니다.
* **`suf_start = mid_start` 정합성**: 작곡할 타겟 윈도우와 완벽히 동일한 범위의 반주를 제공하여 훈련 분포와의 괴리를 원천 차단했습니다.
* **상태 머신 유연화**: `DENSITY` 직후 타겟 악기만 강제하지 않고 원곡에 등장하는 악기들을 모두 허용(`known_inst_ids`)하여, 하이브리드로 학습된 자연스러운 앙상블 분포를 왜곡 없이 디코딩합니다.
* **권장 세팅**: 평탄화 방지를 위해 추론 실행 시 **`temperature` 파라미터를 0.8 ~ 1.0 수준으로 설정**하는 것이 가장 이상적입니다.

## 5. 하이브리드 학습 파이프라인 심층 원리 및 기대 효과

이번에 수정한 61GB의 하이브리드 데이터셋으로 8만 스텝 모델을 이어서 학습(Resume)할 경우, 실제 서비스와 편곡 결과물에서 **체감할 수 있는 4대 핵심 개선 효과**는 다음과 같습니다.

### 1. 뚝뚝 끊기던 선율이 유려하고 길어짐 (선율적 독창성 극대화)
* **기존**: 100% FIM으로만 학습되어 AI가 주어진 반주 코드에 음표를 기계적으로 수렴시키느라 멜로디가 짧고 딱딱했습니다.
* **기대 효과**: Causal 학습 데이터가 융합되면서 AI가 **"음표와 음표 사이를 길고 자연스럽게 전개하는 수평적 작곡 본능"**을 발휘합니다. 기승전결이 뚜렷하고 사람 연주자처럼 호흡이 긴 아름다운 프레이즈를 디코딩해 냅니다.

### 2. 변박 구간에서의 완벽한 칼박 앙상블 (박자 붕괴 원천 차단)
* **기존**: 곡 중간에 4/4에서 3/4나 6/8로 박자표가 바뀌면 마디 계산이 밀려 반주와 타겟 악기가 엇박을 내며 불협화음을 일으켰습니다.
* **기대 효과**: 누적 틱 기반의 무결점 시간 매핑을 거친 데이터를 학습하므로, AI가 각 마디의 정확한 박자표(`METER_*`)를 명확히 인지합니다. **리듬이나 템포가 수시로 바뀌는 복잡한 클래식/재즈 곡에서도 한 치의 오차 없는 정교한 타이밍 앙상블을 완성**합니다.

### 3. "화성은 정밀하게, 연주는 독창적으로" (시너지 효과)
* 데이터로더(`dataset.py`) 분석에서 증명되었듯, FIM 뼈대 구조는 힌트 영역을 무시(`-100`)하고 정답을 채우는 데에만 집중하므로 타겟 악기가 원곡 반주의 화성적 경계선을 절대 침범하지 않습니다.
* 결과적으로 **"원곡 반주의 코드는 완벽하게 존중하면서도, 선율 라인은 독창적이고 세련되게 뽑아내는 최상급 세션 편곡자"**의 역량을 갖추게 됩니다.

### 4. 압도적인 학습 효율성 (단기간 목표 성능 직행)
* 스크래치(처음부터) 학습이 아니라 8만 스텝 동안 쌓은 탄탄한 화성학적 기초 지식 위에 질 좋은 데이터가 얹혀집니다.
* 모델이 새로운 선율적 흐름과 정교한 박자 감각을 스펀지처럼 빠르게 흡수하므로, **비교적 적은 추가 스텝(1~2만 스텝)만으로도 모델이 낼 수 있는 한계 성능에 도달**합니다.

학습이 구동되는 전체적인 뼈대는 **"데이터 공급 → 스마트 마스킹 → 선택적 집중 훈련"**으로 이어지는 정교한 3단계 파이프라인 구조입니다. 전체적인 데이터 흐름과 가중치 업데이트 방식은 다음과 같습니다.

### 🏛️ 하이브리드 학습 시스템의 3단계 작동 구조

#### 1단계: 하이브리드 데이터 공급 (`train.bin`)
전처리기가 원본 악보를 분석하여 **두 가지 형태의 훈련 텐서**를 생성한 뒤, 하나의 거대한 훈련 저장소에 고르게 섞어 넣습니다.
* **타입 A (앙상블 훈련용 FIM 청크)**: 
  `Header` + `[<PRE>] 과거 반주` + `[<SUF>] 미래 반주` + **`[<MID>] 타겟 악기가 포함된 정답 악보`**
* **타입 B (선율 전개용 Causal 청크)**: 
  `Header` + **`순수 악보 전체 (1~16마디)`**

#### 2단계: 스마트 마스킹 (데이터로더의 자동 분기)
데이터로더(`dataset.py`)가 텐서를 AI 모델에 던져줄 때, 프롬프트의 종류를 스스로 감지하여 똑똑하게 채점 기준(`labels`)을 바꿉니다.
* **타입 A(FIM)가 들어오면**: AI가 힌트를 보고 베끼지 못하도록 `<PRE>`와 `<SUF>` 영역의 손실을 `-100`으로 지워버리고, **오직 `<MID>` 이후의 빈칸을 얼마나 완벽히 채웠는지만 채점**합니다.
* **타입 B(Causal)가 들어오면**: 지울 영역이 없으므로, **악보 전체의 수평적 선율 흐름을 처음부터 끝까지 순차적으로 채점**합니다.

#### 3단계: 선택적 집중 최적화 (`WeightedTrainer`)
채점 결과를 바탕으로 Qwen2.5-0.5B의 가중치를 업데이트할 때, 단순 평균을 내지 않고 **음악적으로 중요한 토큰에 강한 페널티**를 매깁니다.
* **조성(`KEY`)을 틀리면**: **`3배`**의 로스를 부과하여 곡 중간에 스케일이 붕괴되는 현상을 막습니다.
* **장르(`GENRE`)를 틀리면**: **`2배`**의 로스를 부과하여 악기 톤과 리듬 스타일의 일관성을 강제합니다.
* **하드웨어 가속**: 이 모든 연산은 SDPA(Scaled Dot-Product Attention) 기술을 통해 **8192 토큰**의 거대한 문맥 위에서 초고속 병렬 처리됩니다.

### 🧩 학습/추론 시 타겟 악기 취급 분업 원리

#### 1. 학습할 때 (정답 맞히기 훈련)
* 힌트로 주는 미래 반주 영역(`<SUF>`)에는 **타겟 악기의 음표를 완전히 삭제(마스킹)**해 버립니다.
* AI는 삭제된 반주만을 듣고, 정답 구역(`<MID>`)에서 **"원래 여기 있던 타겟 악기 파트가 무엇이었는지"**를 예측하여 맞히도록 혹독하게 훈련받습니다.

#### 2. 추론할 때 (실전 창작)
* 실전에서 사용자가 올리는 반주 트랙에는 당연히 타겟 악기 파트가 존재하지 않습니다.
* AI는 **타겟 악기 파트를 전혀 보지 못한 백지상태**에서 오직 반주 화성만을 듣고, 훈련 때 배운 감각과 선율 본능을 발휘하여 **타겟 악기 파트를 스스로 창작해 냅니다.**
